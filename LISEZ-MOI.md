# PhantomStation

> **Version de test :** toutes les consoles peuvent présenter des bugs. La Dreamcast reste particulièrement expérimentale. Utilise **F10** pour signaler un problème et transmettre le journal du jeu.

La compilation PS2 et Dreamcast conserve localement des informations propres à chaque disque. Elles peuvent être reprises lors d’une prochaine compilation du même jeu ; cela ne garantit pas sa compatibilité complète et ne modifie pas automatiquement un jeu déjà créé.

**Pour utiliser PhantomStation :** télécharge `PhantomStation-portable-essai.zip` dans la [version de test GitHub](https://github.com/NovalysDev/PhantomStation/releases), extrais-le dans un dossier et ouvre `PhantomStation.exe`. Les moteurs et outils sont inclus.

**Pour les développeurs :** `PhantomStation-sources-sans-dependances.zip` contient les sources, sans l’EXE ni les outils ; il ne fonctionne pas seul. Ces versions restent expérimentales.

Le sélecteur **FR / EN** du compilateur mémorise la langue de l’interface. Les nouveaux lanceurs PS2 et Nintendo utilisent aussi ce choix, et certains contrôles PS1 sont traduits. Des messages des moteurs et des lanceurs déjà créés peuvent rester dans leur langue d’origine. La langue du jeu dépend de son disque ou de sa cartouche.

PhantomStation propose la création de jeux PS1, PS2, NES, Super Nintendo, Nintendo 64 et Dreamcast. GoldenEye 007 Europe utilise un portage particulier ; les autres jeux N64 utilisent un moteur commun expérimental. La création d’un EXE ne garantit pas que le jeu entier fonctionne.

- **PS1** : choisir le fichier `.cue` avec ses `.bin` à côté, ou une image `.iso` ; ajouter les CD dans l’ordre.
- **PS2** : choisir une image `.iso`.
- **NES** : choisir une cartouche `.nes`.
- **Super Nintendo** : choisir une cartouche `.sfc` ou `.smc`.
- **Nintendo 64** : choisir une cartouche `.z64`, `.v64` ou `.n64`. La compatibilité varie selon le jeu ; le moteur commun est expérimental.
- **Dreamcast** : choisir un fichier `.chd`. Le moteur, le son, les graphismes et les sauvegardes restent expérimentaux.

Extraire d’abord les archives `.7z` ; le format `.chd` est pris en charge pour la Dreamcast. Dans les jeux NES et Super Nintendo, les commandes et réglages s’ouvrent avec F2, les filtres avec F3 et les sauvegardes rapides avec F8/F9. Dans GoldenEye N64, F10 ouvre les réglages du moteur ; les codes sont ceux du jeu. Les options ne sont pas identiques à celles des jeux PlayStation.

Pour signaler un bug, ouvre le jeu depuis la bibliothèque et appuie sur **F10** pendant la partie ou après ton retour dans PhantomStation. Décris le problème, puis choisis si tu veux joindre les sauvegardes et, sur Dreamcast, les blocs de mémoire enregistrés. Après confirmation, le jeu se ferme avant l’envoi de son journal. Une carte partagée peut contenir des sauvegardes d’autres jeux ; les blocs peuvent contenir des données de la mémoire du jeu. Un seul journal limité en taille est conservé par jeu et remplacé à son prochain lancement. F10 reste transmise au jeu et peut aussi ouvrir ses réglages. En cas d’échec de transmission, le détail technique du dernier essai est conservé dans `%LOCALAPPDATA%\PhantomStation\Journaux\envoi-rapport.log`.

Les jeux Nintendo utilisent [RetroRecomp](https://github.com/ArthurReboulSalze/RetroRecomp), [NESRecomp](https://github.com/mstan/nesrecomp) et [SNESRecomp](https://github.com/RetroPortingToolKit/snesrecomp). Les moteurs NES/SNES ont des licences **PolyForm Noncommercial** ; les notices et licences sont conservées dans `nintendo-recomp`. PhantomStation applique un correctif PAL au moteur NES et dirige les données des jeux vers le dossier Documents.

GoldenEye N64 utilise le [portage PC de GoldenEye](https://github.com/jkdansereau/goldeneye-pc-port), compilé pour la version européenne. Il s'agit d'un portage natif à partir du code reconstitué, pas d'un recompilateur universel N64. Les licences et notices sont incluses. Le fichier `.z64` personnel est intégré dans l'EXE ; les données sont extraites au premier lancement dans le cache et les sauvegardes et réglages vont dans Documents.

Les autres cartouches N64 passent par [native-console](https://github.com/RedReaper1515/native-console), un moteur commun expérimental. Il recompile les portions identifiées et interprète le reste ; la création d'un EXE ne garantit pas qu'un jeu est jouable. Une vérification de démarrage est effectuée, mais chaque jeu doit être essayé. Le lanceur affiche jusqu'à quatre manettes reconnues et ouvre leur configuration avec « Configurer les manettes ». Les quatre joueurs partagent les mêmes affectations de touches. Le menu du moteur s'ouvre avec F10 ; F9 affiche les FPS. Les sauvegardes et réglages sont propres à chaque jeu dans Documents. Le menu de codes PlayStation n'est pas disponible.

Les manettes reconnues reçoivent automatiquement les commandes N64 par défaut : stick gauche pour se déplacer, croix pour la croix N64, bouton du bas pour A, bouton de gauche pour B, gâchette gauche pour Z, Start pour Start et stick droit pour les boutons C. Les noms et la disposition physique varient selon la manette : ouvre « Configurer les manettes » pour modifier les touches. Cette configuration est enregistrée et commune aux quatre joueurs du jeu.

« Joueurs » fixe le nombre maximal de manettes : jusqu'à 4 sur PS1 et N64, 5 sur Super Nintendo avec Super Multitap, et 2 actuellement sur NES et PS2. Sur Super Nintendo, le jeu doit être compatible avec le Super Multitap. Sur N64, le mode et le nombre effectif de participants restent à choisir dans le jeu. Exception : le portage dédié de GoldenEye Europe demande 4 dans le compilateur ; le nombre de participants se choisit dans ses menus. Les adaptateurs NES et PS2 pour davantage de joueurs ne sont pas encore pris en charge.

Dans les jeux N64 du moteur commun, « Codes » permet de saisir des codes directs 8 bits `80XXXXXX 00YY` et 16 bits `81XXXXXX YYYY`. Les codes conditionnels, chiffrés et les codes composés ne sont pas pris en charge. À la compilation, PhantomStation cherche une correspondance exacte de l'empreinte SHA-1 dans le catalogue RetroAchievements/BizHawk, puis des codes compatibles dans le catalogue Libretro. Les codes trouvés sont désactivés et leur effet doit être vérifié ; aucun fichier de jeu n'est envoyé. Les autres formats de code Nintendo ne sont pas encore pris en charge.

Depuis la bibliothèque ou le bouton de lancement du compilateur, le lanceur du jeu, son introduction et son affichage sont intégrés dans la fenêtre PhantomStation. Le bouton « Retour au compilateur » demande la fermeture du jeu et retrouve le menu. Un EXE ouvert directement en dehors de PhantomStation conserve son propre lanceur.

Avant une compilation, PhantomStation recherche les jeux de la même console dans la bibliothèque et le dossier de sortie. Il avertit si un nom est similaire ou si l'image semble identique, puis laisse le choix de continuer. Les nouveaux EXE contiennent une petite empreinte calculée sur des portions de l'image ; les anciens jeux sont reconnus par leur nom. Une différence de version, de format ou de nom peut empêcher la détection ; un nom similaire ne prouve pas que les jeux sont identiques.

L'animation utilise le logo et le thème de la console sélectionnée. Les sons PS1 et PS2 utilisent les fichiers déjà fournis. La NES, la Super Nintendo et la Nintendo 64 n'avaient pas de musique de démarrage commune à tous leurs jeux : leurs trois thèmes dans PhantomStation sont des compositions originales, et le son propre au jeu suit normalement. Logos : [NES](https://commons.wikimedia.org/wiki/File:NES_logo.svg), [Super Nintendo PAL](https://commons.wikimedia.org/wiki/File:Super_Nintendo_PAL_logo.png), [Nintendo 64](https://www.mariowiki.com/File:N64_Logo.svg), [PlayStation 2](https://commons.wikimedia.org/wiki/File:PlayStation_2_logo.svg).

Pour les jeux PS2, la recherche de jaquette peut utiliser le numéro du disque dans le [catalogue PCSX2](https://github.com/PCSX2/pcsx2/blob/master/bin/resources/GameIndex.yaml) et les images [Libretro](https://github.com/libretro-thumbnails/Sony_-_PlayStation_2).

Lanceur Windows expérimental pour créer un projet natif avec [PSXRecomp](https://github.com/RetroPortingToolKit/psxrecomp). La génération et la compilation ne garantissent pas que le jeu démarre ou puisse être terminé.

1. Ouvrir **PhantomStation.exe**.
2. Donner un nom au projet et sélectionner les images des disques dans l'ordre (CD 1 puis CD 2). Pour un BIN/CUE, sélectionner de préférence les fichiers CUE : ils décrivent les pistes nécessaires et doivent rester à côté de leurs BIN.
3. Choisir le nombre maximal de joueurs et la résolution interne, puis cliquer sur **Créer le programme**. La résolution 8× est proposée par défaut ; réduire à 4× ou 2× si nécessaire. Jusqu'à quatre joueurs peuvent être configurés pour les titres et périphériques compatibles ; ce réglage ne crée pas un mode multijoueur dans un jeu solo. Une résolution élevée peut demander davantage de ressources ou poser des problèmes selon le jeu. Le journal affiche les étapes et les erreurs. La première génération peut prendre longtemps et utilise Internet pour récupérer les dépendances des projets.
4. Choisir le dossier de destination avec **Choisir le dossier des jeux**. Le lanceur y crée automatiquement un seul EXE, contenant les disques et l’introduction PhantomStation. **Ouvrir le dossier des jeux** permet de retrouver les fichiers créés ; le dossier choisi est mémorisé. Une fois la création terminée, cliquer sur **Terminé** pour choisir si un raccourci doit être ajouté au bureau et, séparément, si les dossiers d’images d’origine doivent être déplacés dans la Corbeille. Le contenu est présenté avant toute suppression ; les dossiers protégés ou non vérifiables sont conservés.

Le bouton **Choisir l’image de l’icône** permet de fournir une jaquette pour l'icône et le lanceur du jeu. Sans image choisie, PhantomStation cherche une correspondance dans les jaquettes Libretro avec le nom du jeu ou du fichier CUE ; ces noms sont envoyés au serveur de jaquettes. Si rien n'est trouvé, il utilise l'image PhantomStation. La source de la jaquette est indiquée dans le projet lorsqu'elle a été téléchargée. Le fond du lanceur utilise l'image PhantomStation par défaut ; on peut aussi choisir une autre image de fond.

Au premier lancement du fichier unique, les données sont extraites dans `%LOCALAPPDATA%\PhantomStation\Jeux` ; ce dossier contient notamment les réglages. Les nouveaux jeux enregistrent leurs cartes mémoire et états de sauvegarde par défaut dans `Documents\PhantomStation\Sauvegardes`, dans un dossier distinct pour chaque jeu. Les jeux créés avant cette modification gardent leur emplacement initial. Si un jeu mis à jour possède d’anciennes sauvegardes dans son cache, elles sont copiées sans écrasement. Les cartes mémoire choisies manuellement restent à leur emplacement choisi. Le fichier unique et la copie extraite occupent donc tous deux de la place. Le premier lancement peut être long. Vérifier soigneusement que le jeu fonctionne avant de déplacer ou supprimer ses images d'origine.

Le jeu affiche d'abord son lanceur. **Réglages** regroupe la résolution, le lissage, la correction 3D, VSync et l’affichage des FPS ; la touche F active ou désactive aussi les FPS en jeu ; des options supplémentaires restent dans **Mods**. Leur effet et leur compatibilité dépendent du jeu. L'introduction PhantomStation apparaît au premier plan après un clic sur **Play**, avant le jeu ; le logo apparaît progressivement, puis le nom du jeu sans les mentions entre parenthèses, sur une image de fond fixe. Si le lanceur est désactivé, l'introduction apparaît directement avant le jeu. Après la création et la vérification de l’EXE, les principaux fichiers intermédiaires de compilation sont supprimés pour économiser de la place. Les images d’origine, les sauvegardes, les réglages et la configuration du projet sont conservés ; utilise l’EXE dans le dossier des jeux choisi pour jouer.

Le lanceur génère un descripteur une piste pour un ISO ou un BIN sans CUE. Cette méthode est expérimentale et ne convient pas à toutes les images ; elle ne reconstitue pas les pistes audio manquantes. Avec plusieurs disques, il enregistre leur identité dans le projet avant compilation ; le changement de disque automatique dépend du jeu et reste à tester. Le projet n'est pas une traduction : utiliser une version française ou une traduction compatible séparée.

Le BIOS PhantomStation personnalisé est proposé par défaut pour les nouveaux projets ; décocher l'option pour utiliser l'OpenBIOS fourni avec PSXRecomp. Son intégration est expérimentale : un essai avec Parasite Eve II a atteint l'introduction du jeu, mais la compatibilité complète et les autres titres restent à vérifier. Elle exige la révision du moteur testée ; le lanceur signale si celle-ci a changé.

Le lanceur requiert Windows, Git pour Windows, Python 3.11 ou supérieur avec Tkinter et Pillow, le dossier `psxrecomp` et la chaîne d'outils `toolchain` présents à côté de `lanceur.py`. Le raccourci utilise un environnement Python disponible sur le système, ou `pythonw.exe` dans le PATH. PSXRecomp est soumis à sa propre licence, notamment son usage non commercial. Le logo PlayStation provient de [Wikimedia Commons](https://commons.wikimedia.org/wiki/File:Playstation_logo_colour.svg). Les données de jeu sont fournies par l'utilisateur.

Le bouton **Codes** propose des codes selon le numéro exact du disque, désactivés par défaut, et permet d’en ajouter manuellement. Les formats non pris en charge ne peuvent pas être activés. La compatibilité de chaque code avec le jeu reste à vérifier. Les données locales proviennent de [DuckStation CHTDB](https://github.com/duckstation/chtdb) et de [Libretro Database](https://github.com/libretro/libretro-database), sous les licences fournies dans assets. Le catalogue ne garantit pas la présence de codes pour chaque jeu français.

Certains disques PAL ont besoin d’un fichier SBI. PhantomStation reconnaît les références répertoriées par [DuckStation](https://github.com/stenzek/duckstation/blob/master/data/resources/gamedb.yaml) et [PSX Data Center](https://psxdatacenter.com/sbifiles.html), recherche le SBI correspondant et l’intègre à l’EXE. Si plusieurs versions existent ou que le téléchargement est impossible, il demande de sélectionner le bon fichier. Le bouton **Choisir fichier(s) SBI** permet aussi de les fournir manuellement. La liste couvre 228 références connues et peut être incomplète ; la compatibilité dépend de la version exacte du disque. L’extraction automatique des archives SBI nécessite 7-Zip ; sinon, choisir un fichier SBI déjà extrait.
